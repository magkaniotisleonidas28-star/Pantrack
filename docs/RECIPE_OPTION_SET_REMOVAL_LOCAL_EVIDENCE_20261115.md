# Removing a recipe option set — local evidence

Recorded: 2026-11-15. Branch: `workstream-c/recipe-option-set-remove`, based on
`main` at `0ec16f9`. A follow-up to the
[option-set screens](RECIPE_OPTION_SCREENS_LOCAL_EVIDENCE_20261115.md), asked
for by the owner. **Local evidence only.** This change adds migration `0047`;
no other schema-bearing change is pending.

## Changed behavior

- **Migration `0047_recipe_option_set_archive`** (additive) adds nullable
  `archived_by` and `archived_at` columns to `recipe_option_sets`.
- **Service**
  ([`d1-recipe-option-sets.ts`](../src/lib/d1-recipe-option-sets.ts)),
  `removeSet`:
  - refuses an unknown set or another company's set, and a removal based on an
    older revision (`concurrent_update`);
  - in one batch, archives the set and deletes its item attachments, both
    guarded so that a concurrent edit or removal refuses the write;
  - then republishes every active item still carrying the set's generated
    options, through the existing atomic recipe publisher, and reports each
    item's result;
  - repeating a removal changes nothing more than republishing items that
    still carry the set's options, so an interrupted removal is finished by
    trying again.
  - Removed sets are no longer listed. They cannot be saved, edited or
    attached, including when removed between the check and the write. Their
    revision history is kept.
- **API:** `removeOptionSetExact` on `/api/inventory` (exact inventory preview
  only) needs an owner or manager of the company, with the existing sign-in,
  cross-site and audit handling.
- **Screens:**
  - Each set has **Remove option set**, which first asks for confirmation and
    names the items that will lose its choices.
  - An item is now also marked "Needs update" when it still carries choices
    from a set it no longer uses, so **Update now** can finish an interrupted
    removal.
- Past sales keep the amounts that applied at the time. A later Clover sale
  still naming a removed choice is held for review.

## Schema review

- **SQL, snapshot and journal:** generated by `pnpm db:generate` from
  [`schema.ts`](../src/db/schema.ts) as two `ALTER TABLE … ADD` statements,
  with `drizzle/meta/0047_snapshot.json` and one journal entry. No triggers,
  indexes or changes to other tables.
- **Fresh and populated databases:** `pnpm db:check` applied all 48
  migrations to fresh SQLite. `pnpm db:migrate:local` applied `0047` to the
  existing local development database, which holds earlier sets, items and
  sales.
- **Compatibility:** existing rows read as not removed. Code from before this
  change ignores the new columns, so it would still list removed sets.
- **Rollback / forward repair:** revert the code; the columns can stay. Never
  edit this migration once applied. To bring back a removed set, a later
  change could clear its archive columns and reattach it.

## Verification

The complete local pipeline passed in this worktree on 2026-11-15 with the
changes staged: `pnpm typecheck`, `pnpm test` (177 suites), `pnpm db:check`
(48 migrations), `pnpm build`, `pnpm db:migrate:local` and `pnpm test:local`.

- [`tests/recipe-option-sets.mjs`](../tests/recipe-option-sets.mjs), with
  sets attached to two items, covers:
  - refusals: a stale removal, and a removal for another company;
  - removal: both items republished, the item's own modifier and other sets
    kept, the set hidden with its archive details recorded and its revision
    history intact;
  - after removal: a sale naming a removed choice is held; repeating the
    removal does nothing; saving, recreating or attaching the removed set is
    refused;
  - an interrupted removal (archived and detached, not yet republished) is
    finished by repeating it.

  Four deliberate code mutations were tried. Three made the test fail:
  listing removed sets, skipping the republish, and attaching removed sets.
  The fourth removed the early revision check, and the database-level
  revision guard still refused the stale removal.
- [`tests/m2-security.mjs`](../tests/m2-security.mjs) covers:
  - the new action joins the per-action cross-company and cross-site checks;
  - anonymous (401), other-company, employee and wrong-company manager
    removals (403) are refused;
  - a stale removal returns 409;
  - a manager's removal republishes the attached item, and the set is then
    hidden from employees' reads.
- **Local browser check**, against `pnpm dev` with the exact preview enabled:
  - the confirmation named the one affected item;
  - the result said "removed. 1 item updated.";
  - the item no longer carried the set's options, and the set was no longer
    listed;
  - no page errors.
