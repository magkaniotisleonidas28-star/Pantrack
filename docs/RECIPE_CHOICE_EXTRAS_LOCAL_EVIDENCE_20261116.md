# More of the picked choice — local evidence

Recorded: 2026-11-16. Branch: `workstream-c/recipe-choice-extras`, based on
`main` at `93de711`. Step 3 of
[decision 0009](decisions/0009-recipe-option-sets.md), with the owner's choice
of a **percentage** recorded in its amendment. **Local evidence only.** This
change adds migration `0048`; no other schema-bearing change is pending.

## Changed behavior

- **Migration `0048_recipe_modifier_extras`** (additive) adds
  `recipe_modifier_extras`: at most one stored extra (choice group and a whole
  percentage from 1 to 100) per recipe modifier version. Triggers allow rows
  only on draft modifier versions and refuse any update, so an activated
  extra is immutable like the version's ingredient changes.
- **Recipe publisher**
  ([`d1-recipe-publisher.ts`](../src/lib/d1-recipe-publisher.ts)): a modifier
  may carry `extra: { groupId, percent }`. It is refused unless the group is
  one of the item's choice groups, the modifier is not itself a pick-one
  option, and the percentage is a whole number from 1 to 100. The extra is
  stored in the same atomic batch as the version.
- **Sales consumption**
  ([`d1-inventory-consumption.ts`](../src/lib/d1-inventory-consumption.ts) and
  the [fake port](../src/lib/inventory-consumption-fake.ts)): for each
  occurrence of a modifier with an extra, adds that percentage of every
  ingredient change of the option picked in the named group on the same line,
  using the picked option's published amount, including per-item overrides.
  The shared rounding helper
  ([`recipe-choices.ts`](../src/lib/recipe-choices.ts)) rounds half away from
  zero to the smallest stored unit. A line missing its required pick is held
  as before, so no extra is guessed. The public v1 consumption contract is
  unchanged.
- **Option sets**
  ([`d1-recipe-option-sets.ts`](../src/lib/d1-recipe-option-sets.ts)): a choice
  in an optional add-ons set may have `extraPercent`. Applying the set links it
  to the item's one pick-one choice group, from a set or the item's own. An
  item with none or with more than one is not updated, and the result says why.
  An item's own modifiers keep their extras when sets are applied, and the item
  builder carries them unchanged.
- **API:** `saveOptionSetExact` choices accept `extraPercent`, and
  `publishRecipeExact` modifiers accept `extra`, both range-checked. No new
  action; existing sign-in, role, company and cross-site checks apply.
- **Reads:** `GET /api/inventory` modifier versions include `extra` when set.
- **Screens** ([`recipe-option-sets.tsx`](../src/components/workspace/recipe-option-sets.tsx)):
  in an "Optional, any number" set, each choice has "More of the picked choice
  (optional)" with a percentage box and a plain explanation. The set list shows
  for example "Light ice: 25% more of the picked choice".

## Schema review

- **SQL, snapshot and journal:** the table, check constraint, snapshot and
  journal entry were generated by `pnpm db:generate` from
  [`schema.ts`](../src/db/schema.ts). Three triggers were appended by hand, in
  the style of migration `0011`.
- **Wrangler splitter and populated database:** `pnpm db:migrate:local`
  applied `0048` to the existing local development database as five commands.
  A query of `sqlite_master` then listed the table and all three triggers.
  `pnpm db:check` applied all 49 migrations to fresh SQLite.
- **Compatibility:** existing modifiers have no extra and behave as before.
  Code from before this change ignores the table, so it would not add the
  extra milk.
- **Rollback / forward repair:** revert the code; the table can stay. To stop
  using extras, clear the percentage on the choice and save the set; attached
  items republish without it. Never edit this migration once applied.

## Verification

The complete local pipeline passed in this worktree on 2026-11-16 with the
changes staged: `pnpm typecheck`, `pnpm test` (178 suites), `pnpm db:check`
(49 migrations), `pnpm build`, `pnpm db:migrate:local` and `pnpm test:local`.

- [`tests/recipe-choice-extras.mjs`](../tests/recipe-choice-extras.mjs) covers:
  - rounding of the shared helper;
  - publisher refusals: unknown group, extra on a pick-one option, and 0, 101
    and 2.5 percent;
  - option-set refusals: extra on a pick-one set, and out-of-range values;
  - applying one ice set to a medium and a large item, each following its own
    milk set, and an item's own modifier keeping its extra;
  - items with no pick-one choice or two are not updated, with the reason;
  - the stored extras refusing update, deletion and insertion once active;
  - sales:
    - medium oat with light ice uses 375 mL (300 + 25%);
    - large whole, changed to 420 mL for that item, with no ice uses 630 mL;
    - regular ice uses only the milk;
    - two items with light ice use 750 mL, and two items with light ice on
      one use 675 mL;
    - syrups are unaffected, and an item's own 10% splash works;
    - a replay changes nothing;
    - light ice without milk is held;
    - another company's sale cannot use these items;
  - editing the set to 30% applies from then on while an earlier sale keeps
    25%, and clearing the percentage republishes without it;
  - the fake port gives the same result and hold.

  Nine deliberate code mutations were tried, and every one made the test fail:
  - ignoring extras in the engine;
  - ignoring the add-on's quantity;
  - ignoring extras in the fake port;
  - dropping a set's extra on apply;
  - dropping an item's own extra on apply;
  - not storing extras;
  - allowing an extra on a pick-one option, in the publisher and in sets;
  - omitting extras from reads.
- [`tests/m2-security.mjs`](../tests/m2-security.mjs): the API refuses
  percentages of 0, 101, 2.5 and "25" for a set choice, and 101 for a recipe
  modifier (400).
- **Local browser check**, against `pnpm dev` with the exact preview enabled,
  with a second fictional local ingredient configured for the milk set:
  - a pick-one set shows no percentage box;
  - an optional set saved Light ice 25% and No ice 50%, and its card showed
    "25% more of the picked choice";
  - attaching milk and ice to an item gave both ice options an extra linked to
    that item's milk set;
  - attaching ice alone showed "“Light ice” adds more of the picked choice, but
    this item has no pick-one choice. Add one first, such as a milk set.";
  - at 390 px wide, the editor had no sideways scrolling and no page errors.

## Not covered

- Choosing which pick-one choice to follow when an item has more than one.
- Setting a percentage on an item-only modifier from the item builder (the API
  supports it, and the builder keeps existing ones).
- Linking choices to Clover options (step 4), hosted D1 and real Clover sales.
