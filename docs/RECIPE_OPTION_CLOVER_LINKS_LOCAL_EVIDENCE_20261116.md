# Linking option-set choices to Clover — local evidence

Recorded: 2026-11-16. Branch: `workstream-c/recipe-option-clover-links`, based
on `main` at `0f596a5`. Step 4 of
[decision 0009](decisions/0009-recipe-option-sets.md). **Local evidence only;
no Clover account was contacted.** This change adds migration `0049`; no other
schema-bearing change is pending.

## Changed behavior

- **Migration `0049_clover_option_links`** (additive) adds
  `clover_option_links`. Each row links one Clover modifier, for the connected
  environment and merchant, to one choice of one option set. A Clover modifier
  can link to one choice per set, so a single Clover "Oat milk" can serve both
  a medium and a large milk set.
- **Service** ([`d1-clover-option-links.ts`](../src/lib/d1-clover-option-links.ts)):
  - `link` refuses an unknown or removed set (including one removed during the
    write), a choice from another set, or a blank name. Relinking within a set
    replaces the earlier choice.
  - `unlink` removes a link; `list` lists the links for one merchant.
  - `resolve` turns a Clover modifier on a recipe into that recipe's generated
    option. It counts only sets that are not removed and choices the recipe has
    carried. When more than one set matches, the set the recipe carries now
    wins; if that is still ambiguous, nothing resolves.
- **Sales mapping** ([`d1-sales-runtime.ts`](../src/lib/d1-sales-runtime.ts)):
  for a Clover sale, a modifier mapped on that item still comes first.
  Otherwise the item's mapped recipe is checked against the links. Links are
  resolved at sale time instead of being copied into per-item mappings, so
  items attached to a set later are covered without linking again. Anything
  unresolved is still held as `unknown_modifier`.
- **API** ([`/api/clover`](../src/app/api/clover/route.ts)): new actions
  `linkOption` and `unlinkOption` for the company owner, with Clover connected.
  They use the same sign-in, cross-site and company checks as item mapping.
  The status read adds `optionSets` (names and choices only) and `optionLinks`.
- **Screens:**
  - Setup & register → Technical connections → Clover gains **Link option-set
    choices** ([`clover-option-links.tsx`](../src/components/workspace/clover-option-links.tsx)).
    The owner picks a set; each choice shows its linked Clover options with an
    unlink button, and a menu of loaded Clover modifiers with **Link**.
  - The option-set card no longer says "coming soon". It now points to that
    panel.
- Disconnecting Clover keeps links, as it keeps item mappings.

## Schema review

- **SQL, snapshot and journal:** the table, its set index, snapshot and journal
  entry were generated by `pnpm db:generate` from
  [`schema.ts`](../src/db/schema.ts). There are no triggers, and the foreign key
  goes to `recipe_option_sets`.
- **Fresh and populated databases:** `pnpm db:check` applied all 50
  migrations to fresh SQLite. `pnpm db:migrate:local` applied `0049` to the
  existing local development database.
- **Compatibility:** the change is additive. Code from before it ignores the
  table, so linked options would be held as before.
- **Rollback / forward repair:** revert the code; the table can stay. Never
  edit this migration once applied.

## Verification

The complete local pipeline passed in this worktree on 2026-11-16 with the
changes staged: `pnpm typecheck`, `pnpm test` (179 suites), `pnpm db:check`
(50 migrations), `pnpm build`, `pnpm db:migrate:local` and `pnpm test:local`.

- [`tests/clover-option-links.mjs`](../tests/clover-option-links.mjs), against
  the real sales mapping port with medium and large items and their own milk
  sets, covers:
  - unlinked options are unknown;
  - one Clover "Oat milk" resolves to each size's own milk choice, and a syrup
    link works;
  - an item without the set, an unmapped item, another merchant, environment
    or company resolve to nothing;
  - an item attached to the set later is covered without relinking;
  - a modifier mapped on one item takes priority;
  - relinking replaces the choice;
  - the same option linked in two sets on one item is held as ambiguous;
  - after a change, the currently carried set wins, and a past-only set still
    resolves for late sales;
  - refusals: unknown set, wrong choice, blank name, another company's set and
    a removed set;
  - a removed set's links stop resolving, and unlinking stops resolution.

  Seven deliberate code mutations were tried, and every one made the test fail:
  - resolving removed sets;
  - ignoring whether the recipe carries the choice;
  - picking the first of ambiguous matches;
  - ignoring past-only matches;
  - ignoring the merchant;
  - linking an unknown choice;
  - ignoring links in the sales runtime.
- [`tests/clover-connection.mjs`](../tests/clover-connection.mjs), with Clover
  mocked, covers:
  - manager, employee and other-company requests are refused (403);
  - validation messages;
  - the owner can link, relink, read and unlink;
  - links record the connected environment and merchant and the owner's email;
  - links survive disconnecting.

  The test's D1 stand-in now reports changed rows under `meta`, as D1 does.
- **Local browser check:** `pnpm dev` with every `/api/clover` request answered
  in the browser, so nothing reached Clover. The page used real local option
  sets. Choosing a milk set, loading two fake Clover modifiers, linking Oat
  milk, and unlinking it all showed the right state and notice. At 390 px wide
  there was no sideways scrolling and no page errors.

## Not covered

- A real Clover sandbox or production merchant, and hosted D1.
- Sales already held for an unlinked option: linking does not change them.
